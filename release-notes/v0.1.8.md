# JumpServer Desktop v0.1.8

本次更新修复 SFTP 连接丢失后无法继续操作的问题，并新增应用内网络代理设置。

## SFTP 断线恢复

- 监听 SSH 连接及 SFTP 通道的断开事件，识别请求返回的连接丢失错误，避免继续复用失效连接。
- 断线后自动尝试一次重新授权并建立连接，保留原文件工作区、当前目录和本地编辑草稿。目录列表、文本读取最多自动重试一次。
- 忽略旧连接迟到的关闭事件；主动关闭工作区或退出登录后，不会恢复旧连接。重新授权失败后停止自动尝试，可重新选择主机建立连接。
- 已完成的传输不会因后续断线改为失败。中断的传输不会自动续传；上传、保存、重命名、删除等写操作不会自动重放，避免重复写入或覆盖文件。
- 修正 SFTP 连接丢失状态码的处理：写入确认丢失时保留“结果未知”，请先核验远端文件状态，不要盲目重复操作。

## 网络代理设置

- 新增 **设置 → 网络**，支持系统代理（默认）、直接连接和自定义 HTTP／HTTPS／SOCKS5 代理，以及代理绕过规则。
- 未登录时也可修改设置；配置保存在本机，旧配置默认沿用系统代理。
- 保存后应用于后续 OAuth 登录、Core 请求、新建 Chen 连接及应用内更新请求，无需重启。现有 Chen 连接需重新连接；系统浏览器和原生 SSH／SFTP 不受影响。
- 自定义代理地址必须包含端口，不支持账号、密码或路径。代理不可用时明确报错，不会静默回退直连。
- OAuth 网络失败提示保留 Chromium 网络错误码，便于排查代理与连接问题，同时不暴露请求地址或凭据。

## 验证

- 本地 18 个测试文件、146 项测试通过，TypeScript 检查及应用构建通过。
- 断线回归覆盖并发读取恢复、旧连接事件隔离、授权失败停止重连、关闭期间取消恢复，以及写入结果未知和已完成下载状态保护。
- SFTP 断线场景使用模拟 SSH／SFTP 验证，未将真实 JumpServer 环境联调列为本次验证结果。
- 正式安装包由 GitHub Actions 在三平台完成检查、构建和打包启动冒烟验证后发布，附带更新元数据、`SHA256SUMS` 和 `release-manifest.json`。

## 下载与更新

- **Windows x64**：NSIS `.exe` 安装包，支持应用内更新。
- **Linux x64**：AppImage 支持应用内更新；`.deb` 请手动下载安装。
- **macOS Intel / Apple Silicon**：选择对应的 x64／arm64 `.dmg` 手动下载安装；macOS 不自动下载或安装更新。
